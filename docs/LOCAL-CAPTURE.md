# 로컬 캡처 패널

바탕화면과 Voicemeeter A1 최종 믹스를 이 PC의 OBS 소스 하나에 공급합니다.

## 처음 연결하기

1. OBS Studio **32.0.1 x64**와 Voicemeeter를 설치합니다.
2. **로컬 캡처 → OBS 연결 준비**를 누릅니다. 플러그인을 처음 설치하거나 업데이트할 때만 OBS를 종료해야 합니다.
3. 해상도·프레임·화면 번호·공통 버퍼·오디오 보정을 설정합니다.
4. **OBS 열고 연결** 또는 **OBS에 연결**을 누릅니다. 편집 중이면 먼저 저장합니다.
5. 현재 선택된 OBS 장면에 **A1 Desktop + Audio**를 자동 추가합니다. 소스 목록이 비어 있어도 되고, 이미 있는 A1 소스는 재사용합니다. 다른 소스나 프로필·장면 모음은 덮어쓰지 않습니다.
6. 미리보기와 오디오 미터를 확인하고 OBS에서 방송 서비스·인코더를 설정한 뒤 **방송 시작** 또는 **녹화 시작**을 누릅니다.

소리를 중복 수집하는 OBS 데스크톱·마이크 소스는 필요에 맞게 꺼두세요. A1 소스에는 마이크·기타·컴퓨터 소리가 이미 함께 들어옵니다. 스튜디오 모드에서는 프로그램에 출력되는 현재 장면을 대상으로 연결합니다.

배포 앱에는 네이티브 바이너리가 포함됩니다. 자동 연결을 위해 Python이나 WebSocket 설정, 특정 장면 모음 선택은 필요하지 않습니다. 소스에서 빌드하려면 Node.js, VS 2022 C++ Build Tools, Windows SDK, CMake를 설치하고 `npm ci` → `npm run build:native` → `npm run app`을 실행하세요. Python은 등록 도구의 개발 테스트에만 사용합니다.

## 실패했을 때

오류 원인과 **다시 시도**가 같은 패널에 나타납니다. 입력한 설정과 이미 설치한 부분은 유지됩니다.

- OBS가 아직 준비 중이면 초기 설정 창을 마치고 다시 시도합니다.
- 연결 도구 업데이트가 필요하면 방송·녹화를 마치고 OBS를 닫은 뒤 다시 시도합니다.
- 설정 파일이 사라졌다면 백업 또는 기본값을 미리 보여줍니다. 저장하거나 연결하면 복구합니다.
- A1 입력 오류라면 Voicemeeter와 A1 출력을 확인한 뒤 다시 시도합니다.
- 재시도는 소스를 중복 생성하지 않습니다. 소스를 삭제했거나 다른 장면으로 옮겼어도 다시 연결할 수 있습니다.
- 소스가 여러 개라면 중복 A1 소스를 정리한 뒤 다시 시도합니다.
- 설치 권한 오류는 모듈 폴더의 Install-OBSPlugin.ps1을 관리자 PowerShell에서 실행한 뒤 다시 시도합니다.

정상 입력을 확인해야 **OBS에 전달 중**으로 바뀝니다. 실행 요청을 보냈다는 이유만으로 성공으로 표시하지 않습니다.

**전달 중지**는 캡처만 끕니다. OBS 방송·녹화는 OBS에서 각각 중지합니다. 실패한 캡처도 별도의 전달 중지 버튼으로 해제할 수 있습니다.

## 설정과 저장

- 가로 320~3840(짝수), 세로 180~2160. 엔진은 15~60 FPS를 지원합니다.
- 화면 번호는 GPU 캡처 열거 순서 기준 1부터 시작하며 Windows 디스플레이 번호와 다를 수 있습니다.
- 공통 버퍼는 200~2000 ms입니다. 오디오 보정은 양수가 지연, 음수가 상대적 선행입니다. 절댓값은 버퍼보다 최소 100 ms 작아야 합니다.
- 버퍼와 보정은 송출용 복사본에만 적용합니다. 헤드폰 모니터링에는 지연을 추가하지 않습니다.
- OBS 캔버스·방송 해상도·FPS는 별도 OBS 설정입니다.
- 물리적 화면·오디오 지연을 자동 측정하지는 않습니다. 측정 없이 완벽한 싱크를 보장하지 않습니다.

**저장**은 파일만 바꾸고, **저장 후 적용**은 실행 중인 캡처를 잠시 재시작합니다. 미저장 변경은 홈 이동 중 유지되며 **되돌리기**로 버릴 수 있습니다. 앱 종료 전에는 저장하세요.

로컬 설정은 local-capture.ini, 직전 저장본은 local-capture.ini.bak입니다. NDI의 sender.ini는 수정하지 않습니다. 기존 주석과 DLL 경로를 보존하며 외부 편집과 충돌하면 덮어쓰기를 거절합니다.

## 제어 방식과 검증

OBS 플러그인이 로컬 전용 Windows named pipe를 제공합니다. 특정 소스나 장면 스크립트가 없어도 동작합니다. 명령은 상태 조회·시작·중지·설정 적용으로 제한하고 요청 크기·만료와 응답을 검사합니다. 외부 네트워크 연결이나 방송·녹화 시작 명령은 제공하지 않습니다.

소스 추가·장면 연결은 OBS UI 스레드에서 실행합니다. 기존 소스는 재사용하고 새로 추가한 장면 항목만 캔버스에 맞춥니다. 중지 시 config_path를 비우고 deck_config_path에 재시작 경로를 보관합니다. 이전 Lua 파일은 마이그레이션용으로 남아 있지만 새 앱의 자동 연결에는 필요하지 않습니다.

`npm run test:ci`는 준비·재시도·설정 복구·IPC 응답·중지 흐름을 검사합니다. `test/smoke-local.cjs`는 별도 Electron 테스트 프로필에서 600×420 패널과 재시도 버튼을 검증합니다. 실제 OBS에서 빈 소스 목록 연결과 1080p60/A1 48 kHz 입력을 확인했으며 방송·녹화는 시작하지 않았습니다.
