# 로컬 캡처 패널

로컬 캡처는 바탕화면과 Voicemeeter A1 최종 믹스를 이 PC의 OBS 소스 하나에 공급합니다. 기존 모듈 ID인 obs는 유지하므로 버튼 위치와 페이지 설정이 보존됩니다.

## 사용 순서

1. **로컬 캡처** 키를 누릅니다. 상단의 **OBS 소스 준비 → 화면·소리 전달 → OBS 방송 시작**이 현재 단계를 보여줍니다.
2. 처음 설치했다면 준비 목록을 확인합니다. **OBS 처음 열기**로 초기 설정을 마친 뒤 OBS를 종료합니다. 준비되면 **OBS 소스 준비**가 플러그인 설치와 A1 Local 프로필·장면 등록을 실행합니다.
3. 해상도·프레임·화면 번호, 공통 버퍼·오디오 보정을 한 화면에서 설정합니다. 소리는 Voicemeeter A1 믹스를 사용합니다.
4. **OBS 열고 전달 시작**을 누릅니다. 편집한 값이 있으면 **저장하고 OBS로 전달**로 표시됩니다. OBS가 이미 열려 있다면 A1 Local 프로파일과 장면 모음을 선택합니다.
5. OBS의 **A1 Local Broadcast** 장면에서 **A1 Desktop + Audio** 화면과 오디오 미터를 확인합니다. 패널의 **OBS에 전달 중**은 캡처가 공급 중이라는 뜻입니다.
6. OBS의 **설정 → 방송**에서 방송 서비스를 연결하고 **설정 → 출력**에서 인코더를 확인한 뒤 **방송 시작**을 누릅니다. 먼저 **녹화 시작**으로 짧게 확인할 수도 있습니다. 패널의 **OBS에서 방송하는 방법**에도 이 순서를 안내합니다.

**전달 중지**는 OBS에 공급하는 캡처만 끕니다. 방송·녹화 종료는 OBS에서 각각 중지합니다. 방송 중/녹화 중 표시는 OBS 제어 연결의 최신 상태를 받은 경우에만 표시합니다.

처음 준비에는 Windows x64, 기본 경로에 설치한 OBS Studio 32.0.1, Voicemeeter와 A1 출력이 필요합니다. 자동 장면 등록에는 Python 3가 필요합니다. 클론한 소스는 `npm ci` → `npm run build:native` → `npm run app` 순서로 준비하며, 배포 앱에는 네이티브 바이너리가 포함됩니다. 준비 버튼은 방송·녹화·캡처를 시작하지 않습니다.

기존 A1 Local 장면 또는 프로필을 덮어쓰지 않습니다. 플러그인 설치 권한이 부족하면 설치 안내의 Install-OBSPlugin.ps1 단계만 관리자 권한으로 실행하고 앱으로 돌아옵니다. 장면 등록은 현재 Windows 계정에서 진행합니다.

**저장**은 파일만 저장합니다. 실행 중인 캡처에는 **저장 후 적용**으로 반영하며 캡처가 잠시 재시작됩니다.

OBS가 닫혀 있으면 캡처 시작이 A1 Local로 OBS를 열고 소스를 시작합니다. OBS가 열려 있으면 해당 장면 모음과 제어 스크립트가 연결돼 있어야 합니다. NDI 송신기가 A1을 사용 중이면 먼저 NDI를 중지합니다.

미저장 변경은 홈 이동 중 유지됩니다. **되돌리기**는 편집 내용을 버리고 현재 저장된 설정을 다시 읽습니다. 미저장 상태에서 캡처 시작을 누르면 먼저 저장한 뒤 시작합니다. 앱을 종료하면 저장하지 않은 편집 내용은 남지 않습니다.

## 설정 범위와 의미

- 해상도: 가로 320~3840(짝수), 세로 180~2160.
- 프레임: 엔진은 15~60 FPS. 패널은 30/60 프리셋과 현재 설정된 다른 값을 보존합니다.
- 화면 번호: GPU 캡처 열거 순서 기준 1부터 시작합니다. Windows 디스플레이 번호와 다를 수 있습니다.
- 공통 버퍼: 200~2000 ms.
- 오디오 보정: 양수는 오디오를 늦추고, 음수는 상대적으로 앞당깁니다. 절댓값은 공통 버퍼보다 최소 100 ms 작아야 합니다.
- 버퍼·보정은 송출용 복사본에 적용합니다. 헤드폰 모니터링에는 지연을 추가하지 않습니다.
- OBS의 캔버스·방송 해상도·FPS는 별도의 OBS 설정입니다.
- 실제 모니터·오인페의 물리적 싱크를 자동 측정하는 기능은 아닙니다. 설정 저장 시 calibration_verified를 false로 재설정합니다.

## 파일과 제어 방식

첫 저장 시 기존 등록 소스의 설정을 바탕으로 같은 폴더에 **local-capture.ini**를 만듭니다. NDI용 sender.ini를 수정하지 않습니다. 직전 저장본은 local-capture.ini.bak에 보관합니다. DLL 경로, 소스 이름과 기존 주석은 보존합니다.

소스 설정의 config_path가 실행 중인 구성 경로입니다. 중지할 때는 이를 비워 네이티브 캡처를 해제하고, 재시작할 경로는 deck_config_path에 보존합니다. OBS 프로세스와 장면의 소스 등록은 유지됩니다.

tools/obs-local-control.lua가 tools/deck-local-control.lua를 로드합니다. 새 설치는 기존 등록 스크립트가 함께 연결합니다. 기존 설치를 갱신할 때는 두 Lua 파일을 같은 tools 폴더에 복사한 뒤 OBS에서 스크립트를 다시 로드하거나 OBS를 다시 실행합니다. OBS에 A1 Local 소스가 정확히 하나 있어야 합니다.

앱은 고정된 로컬 파일 경로를 통해 start / stop / apply만 전달합니다. 외부 네트워크 서버나 WebSocket 활성화는 필요 없습니다. 요청 ID, 만료 시각, 처리 응답과 네이티브 캡처 상태를 확인한 뒤 성공으로 표시합니다. 설정 저장은 메인 프로세스에서 숫자 범위와 파일 리비전을 확인하고 원자적으로 교체합니다. 외부에서 파일이 바뀌면 오래된 편집 내용의 덮어쓰기를 거절합니다.

적용 요청의 응답이 불확실하면 저장 여부와 적용 여부를 구분해 오류를 표시합니다. 상태를 확인하고 되돌리기로 저장값을 읽은 뒤 다시 적용할 수 있습니다.

## 검증

- npm run test:outputs: 설정 검증, 독립 저장, 리비전 충돌, 제어 응답, 기존 출력 가드.
- npm run test:setup: 최초 등록 가드와 상황별 다음 행동.
- npm run test:deck: 공통 모듈 계층과 액션 가드.
- Electron test/smoke-deck.cjs: 600×420 패널 배치, 편집 보존, 저장/적용 구분, 잘못된 입력의 표시, 실행 중 버튼 잠금.
- 실제 OBS에서 동일 설정 적용 → 중지 → 시작과 건강 상태 복원을 검증했습니다. 방송·녹화는 시작하지 않았습니다.
